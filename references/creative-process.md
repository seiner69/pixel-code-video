# 从文案自主创作

## 先确定语义段落

“一个段落”指围绕同一件事展开的一组内容，而非固定秒数、一个镜头或一套动作。先用一句话说明本段在讲什么，并确定观众从段落开头到结尾应多理解什么。例证、对照、因果推进或情绪转折，只要仍服务于这件事，都可以属于同一段。

划分语义段落 → 设计表达关系与视觉事件 → 配音及动作预演 → 确定实际时间。渲染器最终需要数值时长，但数值是这轮设计的结果。没有用户明确时限时，不把文案裁进样例的 6 秒或参考的 8 秒，也不为了凑时长加入动作。素材不足时按语义需要扩展，不因已有模板只有几种动作而删掉必要表达。

检查段落完成度：这一件事是否讲清、各句和各次视觉变化是否相互关联、必要的关系与结果是否可感知。镜头可以继续变化，字幕可以跨镜头保留；不靠变化次数判断段落长短，也不在每次视觉变化后重新起一段。段落间需要承接时，保留有用状态，无需强行重置画面或加入结束卡。

## 把命题转成可见因果

先提取观众需要理解的关系，而不是逐句寻找装饰图标。表达因果时，可写成“因为 A，主体做 B，因此 C 改变”；对照、描述、例证等关系采用相应的视觉组织，不强行改成因果。没有可见结果的动作很容易沦为背景摆动。

| 文案关系 | 可见事件候选 | 保留的结果 |
|---|---|---|
| 零散需求被组织 | 小人递交订单，订单进入同一个容器 | 订单数累积、容器保持装满 |
| 需求确定后生产开始 | 订单从组织者交给工厂，指示灯亮、设备启动 | 机器持续运行，产品进入收集区 |
| 风险被分摊 | 一个大负担拆成多份，分别落到多个参与者 | 每份更小，总量仍守恒 |
| 信任降低交易成本 | 同一买卖双方再次交易，跳过已完成的验证关口 | 历史记录存在，路径变短 |

这些是选项，不是统一叙事模板。论点可能需要对照、累积、遮挡、空间距离或等待，而不需要角色走跳。

## 事件表

简洁记录以下字段，使用 Markdown 表格或 JSON 均可：

```json
{
  "start": 1.2,
  "end": 2.9,
  "meaning": "需求变成可以使用的订单",
  "actor": "organizer",
  "verb": "deliver",
  "target": "factory-input",
  "visual_result": "订单进入工厂，状态灯从暗变亮",
  "result_hold_until": 4.1,
  "caption_group": "需求先聚集，再组织生产",
  "state_after": {"order_owner": "factory", "factory_active": true}
}
```

“接触”与“状态改变”应有明确时刻。对象离开手之前不能提前出现在接收处；切场景不能让已经完成的交易恢复成未完成。

## 时间与阅读

先确定配音文本，再取得实际声音及句段边界。修改文案或配音后更新字幕与动作时间，不把旧配音时码直接套到新文案上。尚无配音时可先制作静音动作预演，但标注暂定时间。

按观众需要完成的观看任务分配时间：注意到新对象 → 识别对象 → 理解关系 → 看见结果。运动可以很快，结果往往需要相对稳定。主体持续放大可能只有一个新事实；小标签依次增加却可能带来多个新事实。

先检查高负担窗口：新字幕、新角色、新空间、数值变化是否挤在一起。常见修正是错开一个事件、延长结果保持、减少无意义装饰，而不是全片乘一个慢速系数。

字幕以可读意群为单位，可跨场景保留。逐字高亮、逐字出现、整句固定高亮是不同选择；根据声音与表达决定，不默认都使用。

## 素材复用与新创作

把绘图函数的外观参数与时间分开，例如肤色、服装、朝向、表情；动作参数为起止时间、位置、目标和持有物。场景代码负责挑选和组合它们。

先复用已有轮廓和动作；现有素材无法表达核心关系时，新增一个有明确用途的道具或动作。不要为了填满所谓素材库一次性制作几十个不会使用的姿势。

需要事实准确性的具体商业、金融或科学说法要单独核查。视觉上表现得顺畅，不会使文案中的事实自动成立。
