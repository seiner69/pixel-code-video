# 从参考视频拆帧到代码

## 证据与解释分开

优先读取本地视频和已完成的拆帧资料。先 probe 真实分辨率、帧率、时长和声音。存在可变帧率时保留逐帧时间戳，不把所有帧强行解释为 `n / 30`。

先看原速完整片段，再看约 0.2–0.3 秒间隔的联系表，最后在变化附近逐帧看。间隔是浏览策略，不是动画节奏要求。脚本 `extract_frames.py` 保存所选区间的每一帧及相对源时间。

为每个变化分别记录：

1. **观察**：这一帧确实发生了什么，哪部分保持。
2. **解释**：可能在强调什么，是否增加新信息；不要声称实测观众情绪或留存。
3. **实现**：平移、缩放、换形、遮罩、粒子或光照，属于可行重建方案，不冒充原作者源码。

## 测量优先级

先确定构图、事件边界、运动方向和结果保持，再测尺寸/位移曲线，最后处理纹理和光照。对象量测要固定口径，例如“红色车身宽度”不能写成“整车宽度”。

除切镜和字幕外，检查：人物姿态/表情、道具归属、图层前后、视线与注意焦点、背景是否移动、音效落点、遮挡、进入与退出的速度、视觉结果是否留下。

不能用帧差峰值直接当切镜。白闪、颜色切换、超大物体缩放都会制造峰值，却不一定改变场景或增加新事实。

## 比较

按同一时间轴并排，默认不改变两边速度。背景、动作、字幕分开检查，再看组合负担。用原速判断实际节奏，用静音慢放辨认动作关系；两者互补。

一轮检查列出具体差异并定位根因，例如面板位移、道具所有权或结果保持。修正这些参数后再导出短段确认，避免反复整体放慢。逐像素相同不是默认目标；明确用户要的是哪种接近程度，并报告剩余差异。
