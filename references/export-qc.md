# 导出和检查

## 运行条件

Python 3.10+；拆帧联系表需要 Pillow。Node.js 22.12+、`puppeteer-core`、本机 Chrome/Chromium、PATH 中的 `ffmpeg` 和 `ffprobe`。模板 package.json 和锁文件声明浏览器控制依赖，执行 `npm ci` 后使用；已有依赖可给渲染器传 `--dependency-root <含 package.json 的目录>`。浏览器无法自动找到时传 `--chrome <可执行文件>`。先读脚本 `--help`。

模板是通用的代码素材起点，不会自动为任意文案生成合适的镜头。扩展 `pixel.js` 的素材和 `motion.js` 的状态采样，修改 `film.js` 的编排。保留原工程的素材和动作接口，优先增量修改。

预览时在项目目录运行 `python -m http.server 5188 --bind 127.0.0.1`，打开 `http://127.0.0.1:5188/studio.html`。直接双击 HTML 可能因浏览器对本地文件读取的限制而无法加载配置。渲染脚本自带临时服务，无需另开预览服务器。

## 画面母版

渲染器启动仅监听 127.0.0.1 的临时静态服务，等待字体，再逐帧调用 `renderAt(frame / fps)`。不录制实时屏幕，因此机器卡顿不会改变片内节奏。默认输出 H.264、yuv420p，尺寸需要偶数。帧数采用初始化时明确保存的 `frames`，实际时长为 `frames / fps`。

脚本另外把几个时间点乱序请求，再与顺序渲染结果比较 SHA-256。它只能证明检查点的寻帧一致性，不能证明剧情或所有帧正确。生成同名 `.render-report.json`。帧序列保留在输出目录下同名 `.frames` 文件夹，便于局部复核。

`--audio` 只使用用户提供或任务已授权的音频。模板默认静音。有音轨时先裁到目标长度，短音轨尾部补静音；这只是封装策略，旁白是否被截断、声画是否匹配仍需实际听。若文案要求完整配音，应以最终语音决定时长，不能用补静音掩盖缺失内容。

## 四种检查分别解决什么

先按完整语义段落验收：整段是否讲清同一件事，事件之间是否连贯。一个镜头或几个动作渲染成功不能代替段落验收；以下检查用于定位整段表达中的具体问题。

1. **看完整速度**：字幕是否来得及读，动作是否表达因果，声音是否压住关键结果。不要仅根据字数/分钟判断。
2. **查事件边界**：接触、归属切换、起跳落地、字幕换组、遮罩开合、场景转换前后几帧。重点看闪回、状态重置、残留、遮挡关系。
3. **看结果保持**：观众能否先识别动作结果，再读取总结。多项任务竞争时，优先错开事件、减少同时进入的对象，局部增加停留；不是一律整体放慢。
4. **查封装和解码**：ffprobe 核对尺寸、fps、帧数、时长、音轨；FFmpeg 全片解码无错误。再抽最终 MP4 的帧，避免只检查网页截图。

## 拆帧工具

`extract_frames.py` 读取源帧时间戳，选择区间内的原帧，输出 PNG、索引 JSON 和联系表。默认每 1 帧都导出；较长视频用 `--every 6` 粗采样，再缩小区间精采样。`--start` 相对视频第一帧时间戳，而不是编码文件的绝对时间原点。`source_pts` 和 `relative_time` 都记录在索引中，VFR 不伪装成 30 fps。可用 `--width` 控制检查图尺寸。

## 并排工具

`compare.py` 用明确的 `--reference-start` 和 `--candidate-start` 对齐，默认各自保持原速。两侧等宽、等高容器，按比例缩放后补黑，不拉伸。左参考、右候选，输出顶部保留文字标签。默认静音；需要听时用 `--audio reference` 或 `--audio candidate`，避免叠加两条声音。

并排片与慢放用于观察，不是相似度证书。报告写明实际残差，如“肩部比例仍有差异”“标题晚 2 帧”“结果只停了 0.2 秒”。几何尺寸匹配、音视频有效、代码可复现，均不能单独证明创作质量。

## 输出保护

初始化与拆帧要求目标目录尚不存在。渲染和并排导出拒绝已有视频、帧目录及同名报告/标签；完成的视频使用同文件系统硬链接排他发布，文件系统不支持时直接失败。不会覆盖旧输出。失败可能留下帧目录或部分已完成文件，请检查后换一个新输出名称重试；多个文件不构成整体事务。

临时服务仅提供模板入口、配置与 src/assets 中允许的资源类型，拒绝跨根目录链接、隐藏文件及其他 Host。只渲染你信任的项目；浏览器执行动画代码并不是安全沙箱。
